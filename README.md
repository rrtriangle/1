# HR Learning Intelligence

전사 교육 이력 관리 및 교육 전략 분석 플랫폼. 기획안의 기능을 Python(Pandas · Plotly · Dash)과
SQLite로 구현했고, **Dataiku DSS의 Dash 웹앱**으로 올려 쓰도록 구성했다. 실제 엑셀 컬럼이 확정되기 전
단계라 **가상 데이터**로 화면과 처리 흐름을 검증했다.

- 기획안 원문: [docs/기획안.md](docs/기획안.md)
- Dataiku 설치 절차: [docs/dataiku_설치.md](docs/dataiku_설치.md)

LMS(신청·결재·출결)를 대체하지 않는다. 교육 이력을 누적·검증하고 분석해 교육 기획에 쓰는 시스템이다.

## 실행

### Dataiku DSS

[docs/dataiku_설치.md](docs/dataiku_설치.md)를 따른다. 요약하면 코드 환경에 패키지 설치 → 프로젝트
라이브러리에 `hrli/` 올리기 → 관리 폴더 만들기 → 노트북에서 초기 설정 → Dash 웹앱에
`dataiku/webapp_backend.py` 붙여 넣기 순서다. Dataiku 안에서의 동작은 아직 확인하지 못했다.

### 로컬(개발·시험)

```bash
pip install -r requirements.txt
python -m hrli.seed --demo                     # DB + 가상 데이터 + 시험용 사용자 4명
HRLI_OTP_DEBUG=1 python -m hrli.web.app        # http://127.0.0.1:8050
python -m unittest discover -s tests           # 적재 규칙·지표 정의·로그인 테스트
```

- 로그인은 이메일 인증 코드 방식이다. `HRLI_OTP_DEBUG=1`이면 메일 대신 **서버 로그에 코드가 출력**된다.
  시험용으로만 쓰고 운영에서는 켜지 않는다.
- 시험용 사용자: `admin@example.com`(시스템 관리자), `trainer@example.com`(교육 담당자),
  `analyst@example.com`(HR 분석 사용자), `manager1@example.com`(조직 관리자, 1공장).
- 실제 운영용 빈 DB는 `python -m hrli.seed --init --admin-email 본인이메일`.
- 데모 적재 후 마지막 달 증분 파일 1건이 **검토 대기** 상태로 남아 있어 데이터 관리 화면에서 검토·승인을 해 볼 수 있다.

| 환경변수 | 기본값 | 의미 |
|---|---|---|
| `HRLI_DATA_DIR` / `HRLI_DB_PATH` / `HRLI_RAW_DIR` | `./data` | DB와 원본 파일 보관 위치(Dataiku에서는 관리 폴더 경로를 코드로 지정) |
| `HRLI_SECRET_KEY` | 한 번 만들어 DB에 보관 | 로그인 세션 서명과 인증 코드 해시에 쓰는 비밀값 |
| `HRLI_HTTPS` | `0` | `1`이면 세션 쿠키를 HTTPS에서만 전송 |
| `HRLI_SMTP_HOST` / `_PORT` / `_FROM` / `_USER` / `_PASSWORD` / `_TLS` | 없음 | 인증 메일을 보낼 SMTP 서버(로컬 실행 시) |
| `HRLI_OTP_TTL` / `HRLI_OTP_ATTEMPTS` / `HRLI_OTP_RESEND` | `10`분 / `5`회 / `60`초 | 인증 코드 유효 시간, 허용 오류 횟수, 재발송 대기 |
| `HRLI_SESSION_HOURS` | `8` | 로그인 유지 시간 |
| `HRLI_MIN_GROUP_SIZE` | `5` | 이 인원 미만 집단은 비율·평균을 가린다 |
| `HRLI_DATE_BASIS` | `start_date` | 기간 집계 기준 일자(`start_date` 또는 `end_date`) |

## 데이터 처리 원칙(코드에 반영된 규칙)

- **원본 보존**: 업로드 파일은 반영 여부와 관계없이 `data/raw/`에 보관한다. 원본 교육명·원본 시간은 덮어쓰지 않는다.
- **배치 단위**: 업로드는 임시 영역에 적재해 기존 데이터와 비교만 한다. 승인하면 한 트랜잭션으로 반영하고, 승인된 배치는 복구(롤백)할 수 있다.
- **명부**: 사번이 식별자다. 매월 스냅샷을 따로 보관한다. 전체 명부에서 빠진 사번은 퇴직 처리하지 않고 `명부미포함`으로만 표시한다. 과거 월을 뒤늦게 올려도 최신 정보를 덮어쓰지 않는다.
- **이력 중복**: ① 원천 이력 ID가 있으면 그것으로, ② 없으면 사번·교육명·기간·기관·시간이 모두 같을 때만 중복으로 본다. ③ 사번·교육명·시작일만 같고 나머지가 다르면 `중복 의심`으로 분류해 담당자가 정하기 전에는 승인되지 않는다. 파일에서 사라진 이력은 삭제하지 않는다.
- **미매칭**: 명부에 없는 사번의 이력은 보관하되 통계에서 뺀다. 명부에 사번이 올라오면 자동으로 포함된다.
- **분류**: 자동 분류는 제안이고 `미확정` 상태로 저장된다. 근거가 없으면 `미분류`로 둔다. 휴넷은 사내·온라인으로 분류하고 분야는 교육명으로 직무/어학만 판별한다. 유사 교육명은 후보만 보여 주고 자동 통합하지 않는다.
- **교육 시간**: 분석용 시간 = 보정값(있으면) 또는 원본. 개별 설정이나 규칙(분야·기관·과정)으로 시간 통계에서만 뺄 수 있고, 참여 건수·인원에는 그대로 남는다.
- **수정 이력**: 모든 수정은 이전 값·새 값·사유·수정자와 함께 `change_log`에, 로그인·개인 이력 조회·다운로드는 `access_log`에 남는다.
- **Dataiku 데이터셋**: 업로드 화면에서 프로젝트 데이터셋 이름으로도 불러올 수 있고, 파일 업로드와 같은 검토 절차를 거친다.

## 지표 정의(`hrli/metrics.py` 한 곳에서 계산)

| 지표 | 정의 |
|---|---|
| 교육 참여이력 건수 | 통계 제외가 아니고 분석 대상 직원과 매칭된 이력 건수 |
| 교육 운영 횟수 | (표준 교육명, 시작일, 종료일, 교육기관)이 서로 다른 조합 수 |
| 교육 참여 인원 | 기간 내 이력이 있는 고유 사번 수 |
| 총 교육 시간 | 시간 통계에 포함되는 분석용 시간 합계 |
| 1인당 평균 교육 시간 | 총 교육 시간 ÷ 고유 참여 인원 |
| 교육 참여율 | 분석 대상 중 참여 인원 ÷ 분석 대상 인원 |
| 분석 대상 인원(분모) | 기간 내 월별 명부에 재직 상태로 한 번이라도 있던 분석 대상 직원. 기간에 명부가 없으면 현재 명부 재직자를 쓰고 화면에 그렇게 표시 |
| 분야 다양성 | 분야별 참여 건수의 정규화 섀넌 지수(0 = 한 분야 집중, 1 = 고른 분포) |
| 편중 지수 | 집단의 참여이력 비중 ÷ 집단의 인원 비중 |

- 진행 중인 기간은 데이터가 있는 마지막 달까지로 잘라서, 전년 동기·직전 기간과 **같은 길이**로 비교한다.
- 소속 기준: `현재 조직`은 현재 명부, `교육 당시 조직`은 교육일과 같은 달의 명부 스냅샷이다. 그 달 명부가 없으면 추정하지 않고 `확인불가`로 표시한다.

## 로그인(이메일 인증 코드)

- 시스템 관리자가 데이터 관리 > 사용자에 등록한 이메일만 로그인할 수 있다. 비밀번호는 없다.
- 이메일을 입력하면 6자리 코드를 메일로 보내고, 그 코드를 입력하면 로그인된다.
- 코드는 1회용이고 10분 뒤 만료되며, 5번 틀리면 폐기된다. DB에는 코드의 해시만 저장한다.
- 등록되지 않은 이메일에도 같은 안내 문구를 보여 줘서 등록 여부가 드러나지 않는다.
- 로그인·실패·코드 발송은 접근 이력에 남는다.

## 요약 기능과 AI

전사 현황의 요약은 Python 집계 결과를 정해진 규칙으로 문장화한 것이다. 사내에서 외부 AI 서비스를 쓸 수 없어
AI 호출은 넣지 않았다. `summary.build_payload`가 만드는 집계 결과에는 개인 식별정보가 없으므로, 나중에 사내에서
승인된 AI가 생기면 그 입력으로 쓸 수 있다.

## 실제 데이터 연동 전에 정해야 할 것(기획안 14장)

현재 값은 가정이며 아래 위치에서 바꾼다.

| 확인 사항 | 현재 가정 | 바꾸는 곳 |
|---|---|---|
| 명부·이력 실제 컬럼명 | 사번, 성명, 교육명, 시작일 등 한글 컬럼 | `column_mapping` 테이블(기본값은 `db.DEFAULT_MAPPING`) |
| 원천 이력 ID 유무 | 있으면 쓰고 없으면 항목 조합 | 매핑에 `source_id` 컬럼 지정 여부 |
| 교육 일자 기준 | 교육 시작일 | `HRLI_DATE_BASIS` |
| 재직 상태 값 | `재직` 또는 빈 값을 재직으로 봄 | `metrics.population` |
| 근속연수 구간 | 3년 미만 / 3~7 / 7~15 / 15년 이상 | `metrics.tenure_band` (RL 연차 기준 확정 시 조정) |
| 휴넷 직무·어학 구분 | 교육명 키워드 | `classify.FIELD_KEYWORDS` |
| 시간 신뢰성 | 데모에서만 어학을 시간 통계 제외 | 데이터 관리 > 교육 시간 |
| DB·서버·인증 | 관리 폴더의 SQLite 파일, 이메일 인증 코드 | `db.py`, `auth.py` |

## 아직 구현하지 않은 것과 한계

- **Dataiku 안에서의 실행 확인.** 개발 환경에 Dataiku가 없어 로컬에서만 검증했다.
- AI 기반 요약(사내 사용 불가로 제외).
- 워드클라우드 이미지(키워드 빈도 막대 차트로 대신함)와 KoNLPy 형태소 분석(정규표현식 토큰화로 대신함).
- 사번 변경·재입사자 통합 매핑(기획안대로 초기에는 사번 단위로 관리).
- 화면에서의 컬럼 매핑 편집(현재는 DB 테이블을 직접 수정).
- 인증 코드 요청에 대한 IP 단위 제한. 이메일 단위 제한(재발송 대기, 오류 횟수)만 있다.
- 대용량 최적화. 조회 때마다 전체 이력을 읽으므로 수십만 건 이상이면 캐시나 집계 테이블이 필요하다.
- SQLite 파일 하나를 쓰므로 웹앱 백엔드는 한 프로세스로만 띄운다. 동시 사용자가 많아지면 사내 DB로 옮겨야 한다.
