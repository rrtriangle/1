2026-10-15 수정본 (아래 2026-10-15 항목 먼저 보세요)

[2026-10-15 전체 점검]
- 01: 기호·조직지향점 판독 보강, 실패 이유 기록, 팀 없는 파트 오류 제거. 처음 한 번 전체 PDF를 다시 읽습니다.
- 02: 그룹 단위 조직·AI 입력 추가, 프롬프트 규칙 변경(쉬운 말 요약 · 문제해결 방식 · 면책 문구 없음).

이 묶음이 현재 사용할 전체 파일입니다.
이전 ZIP에서 코드를 섞어 가져오지 말고 이번 파일을 기준으로 사용하세요.
.py와 같은 이름의 .txt는 내용이 동일합니다. 둘 중 하나만 복사하면 됩니다.
원본 PDF나 직원 명부는 이 묶음에 들어 있지 않습니다.

1. 이번에 바로잡은 부분
=======================
조직지향점은 제공된 베이직 21쪽과 시그니처 32쪽에 모두 있습니다.
기존 01 추출 코드는 도형을 저장했지만 02 집계, AI 입력, 04 화면에서 사용하지 않았습니다.
공통 항목을 최종 보고서까지 연결하지 않은 구현 누락이었습니다.
'현재 사용하지 않아 영향 없음'이라는 설명은 맵/흥미에만 해당하며,
조직지향점 자체를 볼 수 없다는 한계를 제대로 설명하지 못했습니다.

이번 수정:
- 01: 좁은 막대도 읽도록 보완. 네 행/색상/중심/높이를 확인.
- 01: 미추출 메시지에 페이지를 못 찾았는지, 막대 판독에 실패했는지 구분.
- 02: 개인 내 네 막대 길이를 비교해 가장 긴 분야를 보관. 동률 허용.
- 02: 팀/파트별 최상위 분야 인원과 비율, 유효 인원, 동률 인원 집계.
- 02/03: 집계와 분야별 근무 환경 설명을 AI 입력에 포함.
- 04: 팀 조직지향점 분포와 개인 조직지향점 막대 표시.
- 02: 맵 중앙선 판정의 작은 허용 범위를 01과 맞춤.
- 안내문: '아직 웹앱 미구현' 등 이전 단계 문구를 현재 상태로 수정.

조직지향점 활용 방식:
  파랑: 기획/전략
  초록: 영업/마케팅
  빨강: 운영/기술
  노랑: 관리/회계

원본에는 숫자 점수가 인쇄되어 있지 않습니다.
따라서 PDF 막대 길이를 공식 0~100 점수로 부르거나 직원별 길이를 평균내지 않습니다.
개인 화면은 같은 사람의 막대 길이 관계를 보여줍니다.
팀 화면은 각 사람에게 가장 길게 나타난 분야의 인원 분포입니다.
이 집계는 우리 웹앱의 요약 방식이며 버크만 공식 그룹 산출값을 재현한 것이 아닙니다.
다른 세 분야의 정보는 개인 막대에서 확인할 수 있습니다.
동률은 각각의 분야에 포함되므로 비율 합계가 100%를 넘을 수 있습니다.
미추출은 0점이나 가장 짧은 분야로 처리하지 않습니다.

2. 회사 환경과 고정된 입력

2026-07-14 업데이트 공지 기준이며, 이후 업데이트 여부는 미확인입니다.
사용자는 Dataiku/Python 초보이고 사내 PC 패키지 설치에 제한이 있습니다.

ChatGPT는 회사 밖 휴대전화에서 사용하므로 코드/TXT를 사내로 옮겨 붙여 넣는 방식입니다.
우리는 사내 Dataiku에 직접 접속할 수 없습니다.

PDF 원본:
  관리 폴더 ID: XHJjWXOC
  이름: birkman_pdfs
  사번_성명.pdf 형식. 약 746개 업로드 완료, 현재 약 250MB, 최종 약 300~330MB 예상.
  새 PDF는 같은 폴더에 추가합니다. 원본을 다시 업로드할 필요는 없습니다.

인사 명부:
  데이터셋 이름: employee_staff_master
  사번은 string. 앞자리 0을 보존합니다.
  칼럼 순서는 자유이며 No를 제외한 다음 열은 있어야 합니다.
  No / 사번 / 성명 / 재직상태 / 조직명 / 본부명 / 그룹총괄/공장 /
  그룹명 / 팀명 / 파트명 / 직종명 / 직책명 / 직위명 / 사업장 /

대상 직종: 사무직, 기술직, 연구직.
그룹1~3은 베이직, 그룹4는 시그니처. 보고서는 두 종류 공통 항목을 사용합니다.

시그니처에만 있는 추가 관계요소 점수는 팀 공통 보고서에 섞지 않습니다.

4. 처음부터 점검한 연결 기준
===========================
직원 연결:
  파일명 사번을 명부 사번에 연결합니다.
  PDF 본문의 report_name 오타는 연결을 막지 않습니다.
  파일명의 성명과 명부 성명이 다르면 name_review로 확인합니다.
  화면의 이름과 현재 소속은 인사 명부를 사용합니다.
  사번 중복, 서로 다른 복수 PDF는 임의로 합치거나 선택하지 않습니다.

조직 연결:
  본부/그룹/팀/파트 중 빈 단계가 있어도 유지합니다.
  그룹 바로 아래 파트는 정상 파트이며 가짜 팀을 만들지 않습니다.
  여러 사업장/실근무지는 같은 조직 경로라면 같은 팀으로 집계합니다.
  그룹총괄/공장은 표시 경로에서는 숨기지만 현재 조직 키에는 남습니다.
  따라서 실제로 그 칼럼 값 자체가 다르면 같은 팀명도 다른 조직 키가 될 수 있습니다.
  팀 안의 파트 직원은 팀 행과 파트 행에 각각 들어갑니다.
  전사 인원은 이 두 행을 단순 합산하지 않습니다.

진단 없는 직원:
  명단과 소속 인원에는 남습니다. 맵/점수는 채워 넣지 않습니다.
  T/A는 명부에 남고 진단 지표 분모에서 제외합니다. 국적으로 제외하지 않습니다.
  휴직/외부 출향자는 결과가 유효하면 집계에 포함합니다.
  현재 웹앱에는 휴직/출향 제외 필터가 없습니다.
  퇴사하여 현재 명부에 없는 PDF는 직원 결과표/팀 집계에 들어가지 않습니다.

항목별 반영 인원:
  맵은 그 맵의 유효 좌표가 있는 인원.
  흥미는 해당 점수가 있는 인원. 실제 0점은 유효합니다.
  조직지향점은 네 막대를 모두 확인한 인원.
  complete 상태만 보고 모든 항목이 있다는 뜻으로 읽지 않습니다.
  complete는 기존 맵4종+흥미10종+강점 기준이며 조직지향점은 별도 유효 인원을 봅니다.

맵:
  PDF의 실제 기호 좌표를 옮깁니다. 팀 맵을 AI가 그림으로 생성하지 않습니다.
  동일 좌표는 번호를 함께 표시하고 점을 임의로 이동하지 않습니다.
  팀원 화면에서는 개인별 좌표 대신 사분면별 인원 분포를 보여줍니다.
  권한을 가진 리더/인사팀은 개인별 맵과 명단을 봅니다.

AI:
  계산은 02가 하고 설명은 03이 작성합니다.
  shared와 leader 두 종류를 구분합니다.
  input_hash가 맞는 현재 자료의 응답만 사용하며 출력이 잘못되면 설명만 보류합니다.
  근거 ID 검사는 문장 내용의 정확성을 완전히 보증하는 기능이 아닙니다.
  사내 모델 연결과 실제 생성 문장은 아직 여기서 확인하지 못했습니다.

5. 알려준 오류를 이번에는 어떻게 볼 것인가
==========================================
MAP_COLOR_CONFLICT 3건:
  원본 설명의 색과 좌표의 사분면 색이 충돌한 맵입니다.
  해당 맵만 제외하고 다른 정상 맵/흥미/조직지향점은 사용할 수 있습니다.
  3건이 반드시 3명은 아닙니다. 문제 페이지를 보지 않았으므로 원인을 확정하지 않았습니다.
  이번 수정으로 색을 강제로 바꾸지는 않습니다.

ORIENTATION_UNAVAILABLE 114건:
  조직지향점 미추출 알림입니다. 베이직에 없는 항목이라 생긴 것이라고 볼 수 없습니다.
  기존의 좁은 막대 제외 조건을 보완했습니다.
  실제 문제 파일을 보지 않았으므로 114건 전부 해결 여부는 회사 재실행에서 확인해야 합니다.
  미확인 결과는 조직지향점에서만 제외하고 유효 인원을 따로 보여줍니다.
  이 알림 때문에 다른 정상 맵/흥미를 빼지는 않습니다.
  조직지향점 페이지가 이미지이거나 막대가 안 보이는 경우 자동 추정하지 않습니다.

팀 없음/여러 사업장/퇴사자 잔여 PDF:
  사용자 설명을 반영해 전체 진행을 막는 조건으로 쓰지 않습니다.
  현재 명부에 없는 사람이 새 웹앱에 자동 등록되는 것도 아닙니다.

6. 이미 01을 실행한 현재 상태에서 할 순서
=========================================
1) 현재 쓰는 01 레시피의 코드를 이번 01 TXT 전체로 교체.
   PDF_SELECTION 등에 회사에서 지정한 값이 있다면 그 설정은 옮겨 적습니다.
   폴더 ID XHJjWXOC와 명부명은 기본값에 들어 있습니다.
   출력 데이터셋/관리 폴더는 기존 것을 그대로 연결합니다.

2) 01 Run. 완료될 때까지 기다립니다.
   추출 버전이 바뀌어 이번에는 PDF를 다시 읽고 도형을 추출합니다.
   FORCE_REEXTRACT=False 유지. 기존 캐시 폴더는 지우지 않습니다.
   다음 같은 버전 실행부터 변경 없는 PDF의 추출 캐시를 재사용합니다.

3) 기존 02가 있으면 코드를 교체하고 Run.
   없다면 02 안내대로 Python 레시피 하나 생성.
   새 orientation_json/valid_count/profile_json 열은 출력 스키마에 자동 추가됩니다.
   회사에서 출력 스키마 변경 확인창이 나오면 안내된 새 열을 반영합니다.

4) 03 Prompt Recipe를 설정/실행.
   이번 프롬프트 버전은 2026-10-08.2입니다.
   예전 AI 답변은 새 input_hash와 맞지 않아 표시되지 않으므로 갱신합니다.
   입력 칼럼을 결과에서 지우지 말고 Append 대신 전체 갱신을 사용합니다.

5) 04 웹앱 코드와 패키지/메일/폴더 설정.
   새 웹앱이면 Code > Webapps > Dash에서 생성합니다.
   기존 웹앱이면 Python 코드를 교체하고 회사 설정값을 유지한 뒤 재시작합니다.
   기존 birkman_webapp_state는 삭제하지 않습니다. 권한을 다시 입력할 필요가 없습니다.

6) 관리자로 로그인해 익숙한 팀 하나를 선택.
   소속 인원, 맵별 반영 인원, 흥미, 조직지향점 반영 인원 확인.
   그 팀의 이미 알고 있는 결과 한두 명을 원본과 비교.
   AI 설명도 같은 집계와 맞는지 확인.
   그다음 리더 권한을 지정하고 직원 접속을 확인합니다.

다시 PDF를 업로드하거나 프로젝트를 새로 만들 필요가 없습니다.
오류 전체를 0건으로 만들 때까지 기다려야 하는 방식도 아닙니다.

7. 회사에서 바꿀 설정값
=======================
01:
  PDF_FOLDER_ID = XHJjWXOC (이미 반영)
  MASTER_DATASET = employee_staff_master (이미 반영)

8. 로그인·권한·서버 조건
========================
이메일 인증번호는 6자리, 유효시간 5분, 같은 브라우저에서 사용합니다.
회사 도메인과 명부의 유일한 이메일을 확인한 뒤 로그인합니다.
최초 관리자도 이메일 인증을 거칩니다.
관리자는 최초 1인 + 추가 최대 2인입니다.

팀원: 본인 결과 + 소속 팀/파트 공유 집계.
파트장: 지정한 파트의 상세 결과 + 본인 상위 팀의 공유 집계.
팀장: 지정한 팀과 그 아래 파트의 상세 결과.
인사팀: 전체 보고서/개인 결과.
권한 관리자는 조회 역할과 별도입니다.
직책명이 팀장이라고 상세 권한이 자동 부여되지는 않습니다.

새 로컬 관리 폴더 birkman_webapp_state에 SQLite로 권한/로그인 상태를 저장합니다.
단일 DSS 서버의 로컬 디스크, get_path 접근 가능 조건입니다.
컨테이너/다중 서버/NFS 구성이라면 이 저장 방식을 그대로 운영할 수 없습니다.
현재 메일/폴더/HTTPS/비계정 웹앱 공개 연결이 회사 측 확인 사항입니다.
Dataiku 공개 웹앱 설정은 DSS 관리자가 적용하며, 웹앱 자체 인증은 코드에 있습니다.
회사 기존 SSO와 Dataiku 사용자 계정으로 직원 로그인을 대체하지 않습니다.

9. 패키지
=========
01: PyMuPDF. 없으면 코드가 현재 환경에 1.26.6 설치를 시도합니다.
02: Python 표준 라이브러리 + Dataiku 기본 API. 추가 설치 없음.
03: Dataiku에서 제공하는 LLM 연결. 개인 PC 패키지 설치 없음.
04: dash==2.18.2, plotly==5.24.1. 웹앱이 사용하는 Python 환경에 설치.

04는 Dataiku가 Dash부터 불러오므로 본문 안의 자동 설치로 해결할 수 없습니다.
04_requirements.txt를 코드 환경에 등록하거나, 같은 환경의 Python 노트북에서
04_패키지_준비.py/TXT를 한 번 실행합니다. 새 Flow 레시피를 만들지 않습니다.
다른 버전이 이미 있으면 준비 코드가 자동으로 덮어쓰지 않습니다.

Python 3.10 이상. 로컬 검증 환경은 Python 3.12입니다.
DSS 14 공식 Dash 문서에는 1.x 지원 문구가 남아 있습니다.
이번 코드의 Dash 2.18.2/Plotly 5.24.1은 로컬 확인 조합이며,
DSS 14.7.1에서 공식 검증된 조합이라고 주장하는 것은 아닙니다.
회사 Dash 환경의 실제 기동은 설치 후 확인해야 합니다.
