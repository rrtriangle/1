============================================================

[기존 입력 — 새로 만들 필요 없음]
  관리 폴더 이름: birkman_pdfs
  관리 폴더 ID: XHJjWXOC
  직원 명부 데이터셋: employee_staff_master

[이번에 새로 만드는 출력 — 모두 같은 프로젝트]
  ① birkman_people        : 직원 명부 한 행당 결과 한 행
  ② birkman_pdf_files     : PDF 파일 한 개당 처리 결과 한 행
  ③ birkman_issues        : 확인할 항목 목록 (문제가 없으면 0행도 정상)
  ④ birkman_cache         : 관리 폴더. 변경 없는 PDF의 추출 결과 재사용

①~③은 '데이터셋', ④는 PDF를 담았던 것과 같은 '관리 폴더'입니다.
④에는 원본 PDF를 복제하지 않고 추출 결과와 실행 완료 기록을 저장합니다.
이 폴더에도 개인 진단 내용이 있으므로 원본과 같은 접근 범위로 관리합니다.

입력 원본은 바꾸지 않습니다. 출력 세 데이터셋은 실행 때마다 현재 명부와
현재 PDF 목록을 기준으로 갱신합니다. 출력 표를 직접 수정해도 다음 실행에
유지되지 않습니다. 파일 선택 같은 수정은 코드 맨 위 설정을 사용합니다.

============================================================
2. Python 패키지 — 코드에서 자동 설치
============================================================

이제 패키지를 먼저 수동 설치하지 않고 레시피를 실행할 수 있습니다.
코드가 현재 Python 환경에 PyMuPDF가 있는지 확인하고, 없으면 설치한 뒤
PDF 처리를 시작합니다. 이미 있으면 재설치하거나 버전을 강제로 바꾸지 않습니다.

코드 맨 위 기본 설정:
  AUTO_INSTALL_PYMUPDF = True
  PYMUPDF_INSTALL_VERSION = "1.26.6"

설치에는 현재 레시피를 실행하는 Python의 pip를 사용합니다.
서버에 설정된 패키지 저장소·프록시 설정을 그대로 따릅니다.
다른 패키지 저장소나 사용자 설치 경로로 자동 전환하지 않습니다.

자동 설치에 필요한 조건:
  - Python 3.10 이상
  - 해당 Python 환경의 pip와 설치 권한
  - PyMuPDF 1.26.6 설치 파일이 있는 저장소에 서버가 연결 가능

코드에 설치 명령을 넣어도 회사의 설치 권한이나 네트워크 제한을 없앨 수는
없습니다. 제한이 있으면 PDF 처리를 시작하기 전에 원인을 안내하고 멈춥니다.
이 경우 선배님께 아래 패키지를 해당 코드 환경에 설치해달라고 전달하세요.

  PyMuPDF==1.26.6

Dataiku의 dataiku 패키지는 별도로 설치하지 않습니다.
명부는 이미 등록한 데이터셋에서 읽으므로 openpyxl도 필요 없습니다.
Dash는 이번 PDF 처리 코드에서 사용하지 않습니다.
설치 이름은 PyMuPDF입니다. 'fitz'라는 별도 패키지는 설치하지 않습니다.

작성 환경 검증: Python 3.12 / PyMuPDF 1.26.6
다른 버전이 이미 설치돼 있으면 그 버전을 사용하며 로그에 버전을 표시합니다.
문제가 생기면 1.26.6이 설치된 환경으로 맞춰 확인할 수 있습니다.

환경이 유지되면 다음 실행부터는 설치가 생략됩니다. 임시 컨테이너를 매번
새로 만드는 환경이면 설치가 반복될 수 있으며, 이때는 관리자가 코드 환경에
등록해두는 편이 적합합니다. 나중의 Dash 웹앱도 사용하는 환경을 별도로
확인해야 합니다. 레시피에 설치했다고 모든 웹앱에 자동 적용되지는 않습니다.

4. Python 레시피와 출력 연결
============================================================

1) Flow에서 birkman_pdfs 폴더를 선택합니다.
2) 레시피 추가 메뉴(+ Recipe / New recipe 등)에서 Python을 선택합니다.
3) 입력에 birkman_pdfs가 있는지 확인합니다.
4) 최초 출력 데이터셋 이름을 birkman_people로 정하여 생성합니다.
   저장 연결은 회사에서 관리 데이터셋 생성에 허용한 연결을 사용합니다.
   기존에 보였던 filesystem_managed가 이 화면에서도 선택 가능하면 후보입니다.
   이 안내에서는 파일 기반 관리 데이터셋으로 만들 것을 권합니다.
5) 생성된 Python 레시피의 Inputs/Outputs 화면을 엽니다.
6) Inputs에 기존 데이터셋 employee_staff_master를 추가합니다.
7) Outputs에 새 데이터셋 birkman_pdf_files, birkman_issues를 추가합니다.
8) Outputs에서 Add → Create folder로 birkman_cache 관리 폴더를 만듭니다.
   폴더 생성이 별도 화면에 있으면 먼저 만든 후 기존 출력으로 연결해도 됩니다.

최종 연결 확인:

  Inputs  : birkman_pdfs (XHJjWXOC)
            employee_staff_master

  Outputs : birkman_people
            birkman_pdf_files
            birkman_issues
            birkman_cache (Folder)

출력은 Append/추가 모드가 아닌 전체 갱신 모드로 둡니다.
파티션은 사용하지 않습니다. 캐시 폴더를 실행 전에 비우는 설정도 사용하지 않습니다.
캐시를 Inputs에도 연결할 필요는 없습니다. 레시피는 자신의 출력 폴더에
지난 실행 결과가 있는지 확인한 후 재사용합니다.

9) 레시피의 Settings에서 Python 3.10 이상 코드 환경을 선택합니다.
   PyMuPDF가 없는 경우는 코드가 실행 시작 시 설치를 시도합니다.
10) Code 탭의 자동 생성 예제 코드를 전부 지웁니다.
11) 01_birkman_extract_recipe.txt를 메모장으로 열어 전체 복사한 뒤 붙여 넣습니다.
    .py 파일과 .txt 파일의 본문은 동일합니다. 붙여 넣기에는 하나만 사용합니다.
12) 저장한 후 Run을 누릅니다.

정해진 이름으로 만들었다면 코드 수정 없이 실행하도록 설정되어 있습니다.
'birkman_cache를 찾을 수 없음'이 발생하면 폴더 연결/이름을 먼저 확인합니다.
필요하면 코드 맨 위 CACHE_FOLDER에 해당 폴더의 ID를 넣어도 됩니다.

5. 실행 중 확인할 것
============================================================

실행 로그에는 직원 이름이나 진단 설명 대신 처리 건수만 표시됩니다.
25개마다 진행 상태가 출력됩니다.

  PDF 처리 25/746 · 캐시 재사용 0

위 숫자는 표시 형식 예시이며 실제 폴더의 PDF 수에 따라 달라집니다.
첫 실행의 실제 소요 시간은 서버 자원과 PDF 형식에 따라 달라집니다.

완료하면 다음 합계가 로그에 나옵니다.
  - 명부행수 / PDF개수
  - PDF추출상태: complete / partial / failed
  - 명부연결상태별 인원
  - 분석가능인원 / 확인항목수 / 캐시재사용파일수

같은 레시피를 동시에 두 번 실행하지 않습니다.
완료되면 birkman_cache/latest_success.json에 해당 run_id가 기록됩니다.
세 데이터셋은 단일 트랜잭션으로 갱신되지는 않습니다. 다음 단계 웹앱은 실행
완료 기록과 run_id를 확인하고, 갱신 도중이거나 실패한 결과를 서비스하지
않도록 연결했습니다. 실행 중간의 출력 표를 완성 결과로 배포하지 마세요.

6. 결과표 읽는 방법
============================================================

[birkman_people]
명부의 구성원을 유지한 표입니다. 한 사번이 명부에 중복되면 중복 행도 남기고
연결을 보류하므로, 중복이 없는 명부에서만 직원 한 명당 한 행이 됩니다.

diagnosis_status:
  complete          공통 맵 4종 + 흥미 10종 + 강점 설명 추출 완료
  partial           일부 항목만 추출. 유효한 항목만 사용 가능
  missing           해당 사번 PDF가 현재 폴더에 없음
  excluded_ta       직위명 T/A. 명단 유지, 분석 제외
  duplicate_review 서로 다른 PDF가 여러 개여서 선택 필요
  name_review       명부와 PDF 파일명의 성명 불일치
  master_review     명부 사번 중복 또는 사번·성명 형식 확인 필요
  failed            PDF를 열거나 공통 항목을 추출하지 못함

분석용 기본 조건:
  analysis_eligible = true
  + 해당 항목의 유효 여부 확인

예: 평소행동 맵은 usual_valid = true인 사람만 사용합니다.
    흥미 차트는 analysis_eligible = true이고 해당 흥미 값이 빈칸이 아닌 사람만
    사용합니다. T/A/잘못 연결된 결과를 원시 점수 열만 보고 집계하지 않습니다.

휴직자와 외부 출향자도 결과가 정상이라면 기본 분석에 포함됩니다.
is_on_leave / is_seconded를 별도 보관합니다. 현재 웹앱에는 휴직/출향 제외 필터가 없으며 기본 집계에 포함됩니다.
휴직·출향으로 결과가 없는 경우와 아직 미진단인 경우를 코드가 추정하지 않습니다.

T/A는 직위명 기준입니다. 일본 국적이라는 이유로 자동 제외하지 않습니다.
T/A에게 PDF가 있으면 제외 상태를 유지하면서 확인 목록에 알립니다.

조직:
  team_key / part_key: 열 이름과 상위 경로를 반영한 내부 식별값
  org_path: 공장 단계를 생략한 화면 표시용 경로
  org_path_full: 공장 단계를 포함한 원본 경로
  org_status: resolved / team_unassigned / review_multi_site

그룹·본부가 빈칸이어도 팀명이 있으면 팀으로 연결합니다. 팀명 없이 파트명만 있으면 그룹 직속 파트로 연결합니다.
팀명이 없는 직속·상위 직책자는 별도로 남기며 특정 팀에 임의 배정하지 않습니다.
같은 팀 경로에 여러 사업장이 있으면 동일 팀인지 확인하는 안내가 생깁니다.
이는 곧 오류라는 뜻은 아닙니다. 실제 다사업장 팀이면 그대로 사용할 수 있습니다.
조직명이 바뀌면 키도 바뀝니다. 향후 리더 권한 화면에서 조직 변경을 확인해야 합니다.

계정:
  email_normalized: 앞뒤 공백 제거, 소문자 변환한 이메일
  email_mapping_ok: 회사 도메인 형식 및 명부 내 중복 확인 결과
  leader_candidate: 직책명에서 만든 '권한 설정 참고값'

email_mapping_ok는 메일 소유 인증이나 로그인 허용을 의미하지 않습니다.
leader_candidate도 실제 권한을 부여하지 않습니다. 관리자 권한·조회 범위와
메일 인증은 웹앱 단계에서 별도로 구현합니다.

[birkman_pdf_files]
원본 PDF 각각의 경로, SHA256, 페이지 수, 추출 상태, 캐시 재사용 여부를 저장합니다.
payload_json에는 페이지 출처·원본 도형 위치·설명 등이 들어 있습니다.
모든 직원의 결과가 포함될 수 있으므로 인사 담당자의 확인용입니다.
웹페이지에 이 표 전체를 보내는 용도로 쓰지 않습니다.

[birkman_issues]
employee_id / source_path / source_page / issue_code / message를 확인합니다.
warning은 검토가 필요한 항목, info는 참고 안내입니다.
결과지가 없는 모든 사람을 오류 행으로 만들지는 않습니다.
그 인원은 birkman_people의 missing으로 확인합니다.

7. 추출 규칙과 범위
============================================================

맵:
  고정 페이지 번호 대신 '흥미 탐색', '욕구 탐색' 등의 제목을 찾습니다.
  사분면의 색·배치를 확인한 뒤 흰색 기호의 선/곡선 도형을 읽습니다.
  별/다이아몬드/원/사각형을 독립적으로 읽습니다.
  욕구 좌표를 스트레스 좌표로 복사하지 않습니다.
  전체 맵 또는 요약 맵이 있으면 상세 맵과 위치를 대조합니다.
  좌표와 본문 색상 설명이 충돌하면 해당 맵만 확인 대상으로 돌립니다.

좌표:
  중심 (0, 0), 왼쪽 -1, 오른쪽 +1, 아래 -1, 위 +1
  x축: 왼쪽 과제지향 / 오른쪽 사람지향
  y축: 아래 내향 / 위 외향
  원본 PDF상의 위치를 공통 도면으로 옮긴 좌표이며 별도의 성격 점수가 아닙니다.

흥미:
  항목명과 같은 칸의 백분율 숫자를 연결합니다.
  점수 내림차순 같은 텍스트 순서에 의존하지 않습니다.
  10개를 1:1로 연결하지 못하면 임의 배치하지 않고 확인 대상으로 표시합니다.
  점수 합계를 100%로 만들거나, 능력 점수로 변환하지 않습니다.

설명:
  맵 페이지의 일반적인 색상 설명과 개인별 설명을 구분합니다.
  화면용 personal_json에는 개인 위치에 해당하는 설명을 저장합니다.
  문장 요약/새 해석은 이 레시피에서 생성하지 않습니다.

조직지향점:
  원본 막대의 사각형 위치·길이를 도형 정보로 보관합니다.
  인쇄되지 않은 0~100 점수를 임의로 만들지 않습니다.
  02 단계에서 개인별 가장 긴 분야의 인원 분포를 집계하고 04 웹앱에서 표시합니다.
  4개 막대가 모두 확인된 결과만 사용하며 동률은 함께 표시합니다.
  좁은 막대를 가로/세로 비율 때문에 제외하던 조건을 제거했습니다.
  ORIENTATION_UNAVAILABLE은 이제 페이지 미발견/막대 판독 실패를 메시지로 구분합니다.
  complete는 기존 맵·흥미·강점 기준입니다. 조직지향점은 orientation_json을 별도로 확인합니다.

인쇄일:
  print_date는 PDF의 '인쇄일'입니다. 진단 실시일로 사용하지 않습니다.

이미지 PDF / 다른 도형 형식:
  이미지 PDF는 PDF_IMAGE_ONLY 등으로 표시합니다. 자동 OCR은 포함하지 않습니다.
  원본의 기호가 벡터가 아닌 다른 형태이면 해당 항목이 partial로 남을 수 있습니다.
  사내 베이직 원본은 아직 직접 검증하지 못했으므로 첫 실행의 항목별 결과를
  확인해야 합니다. 페이지 번호와 페이지 수 차이는 코드가 허용하도록 만들었습니다.

============================================================
8. 중복 파일과 재실행
============================================================

같은 사번으로 완전히 같은 PDF가 여러 폴더에 있으면 SHA256이 같으므로 한 번만
집계합니다. 내용이 다른 PDF는 최신 인쇄일 등을 근거로 임의 선택하지 않습니다.

여러 PDF 중 사용할 것을 확인했다면, 코드 맨 위 PDF_SELECTION에
사번과 birkman_pdf_files의 source_path를 추가한 뒤 다시 실행합니다.

  PDF_SELECTION = {
      "000000": "/하위폴더/000000_예시.pdf",
  }

위 값은 형식 예시입니다. 실제 사번과 경로를 사내에서 넣습니다.
가능하면 잘못 업로드한 사본을 원본 폴더에서 정리해도 됩니다.

이번 수정본 적용:
  추출 버전 변경으로 이번 한 번은 PDF를 다시 추출합니다. FORCE_REEXTRACT=False를 유지합니다.
  이전 캐시는 지울 필요가 없습니다. 새 버전 경로에 저장한 후 다음 실행부터 재사용합니다.
  01 완료 후 02 집계, 03 프롬프트 순서로 실행합니다.

일반 갱신:
  1) 새 PDF를 birkman_pdfs에 추가
  2) 명부 변경 시 employee_staff_master의 원본을 교체하고 표 갱신
  3) 같은 Python 레시피 Run

파일 내용 해시가 같은 PDF는 지난 추출 결과를 재사용합니다.
해시 확인을 위해 PDF 파일은 매번 읽지만, 도형·텍스트 추출은 생략합니다.
명부 연결과 상태 필터는 매번 새로 계산하므로 조직 이동을 반영합니다.
PDF 폴더에서 삭제된 파일은 캐시가 남아 있어도 다음 집계에서 빠집니다.
캐시는 과거 개인 결과를 담고 있으므로 보관 필요가 없으면 담당자가 정리할 수
있습니다. 지워도 원본이 있으면 다음 실행에서 다시 추출됩니다.

============================================================
9. 오류가 나면
============================================================

PyMuPDF 자동 설치 실패:
  오류에 표시된 설치 권한·저장소 연결·Python 버전을 확인.
  설치 제한이 있으면 선배님/관리자에게 PyMuPDF==1.26.6 설치 요청.

PyMuPDF는 설치돼 있지만 불러오지 못했습니다:
  선배님께 현재 코드 환경의 PyMuPDF 설치 상태를 확인 요청.
  설치를 수정한 다음 레시피를 다시 실행.

not declared as input or output / not found:
  4번의 입력 2개·출력 4개와 이름/폴더 ID 확인.

명부에 필요한 열이 없습니다:
  오류에 나온 열 이름과 실제 엑셀 머리글 확인.
  빈값은 허용하지만 해당 열 자체는 있어야 함.

사번 스키마를 string으로 변경하세요:
  명부 Schema의 사번 형식 확인. 앞자리 0 손실 여부도 원본과 비교.

NAME_MISMATCH:
  사내에서 PDF 파일명의 성명과 명부 성명을 비교.
  PDF 본문/표지의 report_name은 진단 당시 입력 오타가 있을 수 있으므로
  직원 연결 기준으로 사용하지 않습니다. 파일명은 사번_성명.pdf 형식이어야 합니다.
  복사본 접미사 '(1)' 등이 붙은 파일명도 확인 대상이 됨.

MAP_MISSING / MAP_SYMBOL_NOT_UNIQUE / INTERESTS_INCOMPLETE:
  안내된 PDF 페이지를 사내에서 확인. 원본 형식 차이에 맞춰 추출기를 조정해야 함.
  전체 명부/결과지는 외부로 보내지 않아도 됨. 우선 issue_code와 건수만 공유.

PDF_READ_ERROR:
  해당 파일이 실제로 열리는 PDF인지, 전송이 완료됐는지, 개별 크기 제한에
  걸렸는지 확인. 잠금 PDF는 PDF_ENCRYPTED로 별도 표시됨.

캐시 폴더 쓰기 실패:
  birkman_cache가 출력으로 연결돼 있고 저장소 쓰기 권한·용량이 있는지 확인.

============================================================
10. 작성 환경에서 확인한 범위
============================================================

제공받은 실제 시그니처 원본:
  - 맵 4종 좌표 및 전체/요약 맵 대조
  - 흥미 10개 항목·점수
  - 개인별 설명과 강점 문장
  - 조직지향점 막대 도형

해당 원본을 이용한 페이지 순서/수/크기/회전 변경 검증과,
중복 PDF·명부 중복·이름 불일치·휴직/출향/T/A·캐시 재사용 검증을 수행했습니다.
실제 사내 Dataiku 서버에서는 아직 실행하지 않았습니다.
제공된 베이직 이미지 PDF 21쪽에서 조직지향점의 존재와 형식을 확인했습니다.
마스킹 전 텍스트/벡터 베이직 원본에 대한 실제 추출 검증은 아직 못했습니다.
114건의 문제 PDF도 미확인이라 이번 보완으로 전부 해결된다고 보장하지 않습니다.

첫 실행 후 알려주면 좋은 것:
  로그 끝의 집계 숫자, 또는 birkman_issues의 오류 코드별 건수.
  직원 이름·이메일·전체 사번·결과지 내용은 보내지 않아도 됩니다.
  이 결과가 Dash 팀 리포트에서 표시할 실제 데이터의 기준이 됩니다.
