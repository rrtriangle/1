이번에 할 일
============
기존 PDF 추출 레시피 뒤에 새 Python 레시피를 하나 추가합니다.
기존 01_birkman_extract_recipe 코드를 이 코드로 바꾸는 것이 아닙니다.
이미 만들어진 birkman_people를 읽어서 조직별 자료를 만듭니다.

PDF 누락, 조직지향점 추출 누락, 팀 없음, 여러 사업장 안내가 있어도 진행합니다.
기존 birkman_issues를 집계 중단 조건으로 사용하지 않습니다.
없는 진단 값은 평균에 0으로 넣지 않고 그 항목의 집계 분모에서 제외합니다.

그룹 바로 아래의 파트도 정상 파트입니다. 임의로 팀을 만들어 끼워 넣지 않습니다.
같은 팀의 사업장/실근무지가 여러 곳이면 같은 팀으로 묶습니다.
팀 내부 파트에 속한 직원은 팀 집계와 파트 집계 양쪽에 각각 들어갑니다.

1. 입력과 출력 만들기
=====================

[입력 — 기존 항목 2개]
  데이터셋   birkman_people
  관리 폴더  birkman_cache

[출력 — 새 항목 4개]
  데이터셋   birkman_org_summary
  데이터셋   birkman_org_members
  데이터셋   birkman_ai_inputs
  관리 폴더  birkman_team_cache

birkman_team_cache는 새로 만드는 별도 관리 폴더입니다.
기존 birkman_cache나 PDF 원본 폴더 XHJjWXOC를 출력으로 넣지 마세요.

순서:
  1) Flow에서 birkman_people를 선택합니다.
  2) 새 Python 레시피를 만듭니다.
  3) 첫 출력 데이터셋 이름을 birkman_org_summary로 지정합니다.
  4) 레시피의 Inputs/Outputs에서 기존 관리 폴더 birkman_cache를 입력에 추가합니다.
  5) 나머지 출력 데이터셋 birkman_org_members, birkman_ai_inputs를 추가합니다.
  6) 새 관리 폴더 birkman_team_cache를 만들고 출력에 추가합니다.
  7) 세 출력 데이터셋은 전체 갱신으로 설정합니다. Append는 사용하지 않습니다.
  8) 파티션은 사용하지 않습니다.
  9) Python 환경은 앞 단계에서 실행에 성공한 환경을 그대로 선택합니다.
 10) 자동 생성된 샘플 코드를 지우고 02_birkman_team_recipe.txt 전체를 붙여 넣습니다.
 11) 저장 후 실행합니다.

출력 연결은 앞 단계에서 사용한 회사의 관리 데이터셋용 연결을 사용하면 됩니다.
SQL 대신 파일 기반 관리 데이터셋 연결을 쓰면 긴 JSON/프롬프트 칼럼을 다루기 편합니다.
SQL 연결을 쓸 경우 긴 문자열이 잘리지 않는 칼럼 형식이어야 합니다.

이 레시피는 Python 기본 라이브러리와 Dataiku 기본 API만 사용합니다.
새 패키지 설치나 PC 폴더 경로 입력이 필요하지 않습니다.

폴더를 이름으로 찾지 못하면 코드 맨 위의 두 값만 실제 관리 폴더 ID로 바꿉니다.
  EXTRACT_CACHE_INPUT = "기존 birkman_cache의 ID"
  TEAM_CACHE_OUTPUT = "새 birkman_team_cache의 ID"
PDF 폴더 ID XHJjWXOC와 혼동하지 마세요.

2. 결과표별 역할
===============

[birkman_org_summary — 조직 한 개당 한 행]
팀과 파트를 각각 별도 행으로 만듭니다.
팀/파트가 없는 상위 직책자는 '그룹 직속' 등 별도 명단용 행에 남깁니다.

먼저 볼 칼럼:
  org_name                  조직명
  org_level                 team / part / group_direct 등
  org_path                  본부·그룹·팀·파트의 표시 경로
  org_path_full             그룹총괄/공장까지 포함한 구분 경로
  direct_part               팀 없이 상위 조직 바로 아래 있는 파트이면 true
  member_count              조직 명부 인원. 진단 없는 직원과 T/A도 포함
  target_count              명부 인원 중 T/A를 제외한 인원
  analysis_count            사용할 수 있는 진단 결과가 있는 인원
  analysis_coverage_pct     analysis_count / target_count × 100
  missing_count             PDF가 연결되지 않은 인원
  ta_count                  T/A 인원
  leader_count              팀의 팀장 또는 파트의 파트장 인원
  leader_analysis_count     위 리더 중 유효 진단이 있는 인원
  usual_valid_count         평소행동 맵에 실제 들어가는 인원
  needs_valid_count         욕구 맵에 실제 들어가는 인원
  interest_numerical_mean   숫자 흥미 점수의 산술평균

interest/usual/needs/stress 각각의 valid_count를 별도로 보관합니다.
흥미 항목 10개도 각각 mean과 valid_count를 따로 보관합니다.
진단 보유율과 각 지표의 유효 인원은 서로 다를 수 있습니다.

JSON 칼럼:
  maps_json                맵별 사분면 인원/비율과 좌표 평균
  interests_json           흥미별 유효 인원, 평균, 중앙값, 최솟값/최댓값, 점수 분포
  orientation_json         조직지향점 최상위 분야별 인원·비율·동률·미확인 인원
  orientation_valid_count  네 조직지향점 막대가 모두 유효한 인원
  leader_comparison_json   해당 조직 리더와 나머지 구성원의 별도 집계
  sites_json               사업장별 명부 인원
  workplaces_json          실근무지별 명부 인원
  coverage_json            인원과 결과 보유 상태

좌표 평균은 분포의 보조 정보이며 새로운 '팀 버크만 유형'이 아닙니다.
흥미 점수 평균도 별도의 팀 백분위로 환산하지 않습니다.
조직지향점은 같은 사람의 네 막대 길이를 비교하고 가장 긴 분야별 인원을 집계합니다.
다른 PDF의 막대 길이를 서로 평균내거나 공식 0~100 점수로 환산하지 않습니다.
동률은 해당 분야에 각각 1명씩 포함하므로 비율 합계가 100%를 넘을 수 있습니다.
미추출은 해당 항목에서만 제외하며 나머지 맵·흥미는 유지합니다.
orientation_json의 missing_count는 분석 가능 인원 중 조직지향점 미확인 인원입니다.
구성원표에는 orientation_valid / orientation_profile_json을 추가했습니다.
미세한 길이 차이(최대 길이의 0.2%, 최소 0.01 PDF 단위)는 반올림 오차로 보고 동률 처리합니다.

[birkman_org_members — 조직과 직원의 연결표]
직원 이름, 사번, 소속, 상태, 맵의 실제 좌표, 흥미 점수를 보관합니다.
진단이 없는 직원도 행이 남습니다. 좌표와 점수만 비어 있습니다.
팀 맵을 그릴 때 이 표의 x/y를 그대로 사용하면 됩니다.
겹치는 점의 좌표를 임의로 바꾸지 않았습니다.

팀 안에 파트가 있으면 한 직원은 팀 행과 파트 행에 각각 한 번씩 나타납니다.
따라서 이 표의 전체 행 수를 전사 인원수로 사용하면 안 됩니다.
primary_membership=true인 행만 보면 직원 한 명당 한 행입니다.
팀/파트 키는 1단계 추출 레시피의 키 규칙과 맞춰서 생성했습니다.

is_org_leader는 집계상 팀장/파트장 구분이며, 로그인 권한을 부여하지 않습니다.
팀장은 팀 전체 집계에 포함됩니다. 파트장은 소속 파트와 팀 집계에 포함됩니다.

[birkman_ai_inputs — 조직·대상별 한 행]
유효한 진단이 있는 팀/파트/그룹 하나당 다음 두 행이 생성됩니다.
  audience=shared : 구성원 공유용 설명
  audience=leader : 팀장/파트장/그룹장·인사팀용 설명 및 리더 참고사항

주요 칼럼:
  ai_ready          이번 출력은 AI 생성 대상만 남으므로 모두 true
  skip_reason       기존 스키마 호환용 칼럼. 이번 출력에서는 빈값
  prompt_text       모델에 전달할 완성된 한국어 프롬프트
  input_json        프롬프트에 들어간 실제 집계 근거
  input_hash        입력과 프롬프트의 내용이 같은지 구분하는 해시
  prompt_version    프롬프트 버전
  prompt_chars      프롬프트 글자 수. 토큰 수는 아님
  evidence_omissions 길이 제한으로 생략된 원문 근거 수

진단 없는 조직과 현재 범위 밖인 상위 직속 명단은 AI 입력표에 넣지 않습니다.
해당 조직과 구성원은 요약표/구성원표에 그대로 남습니다.
birkman_ai_inputs를 바로 Prompt Recipe에 연결하면 됩니다.
별도 Prepare/Filter 레시피나 birkman_ai_ready 데이터셋은 만들지 않습니다.

인원수·평균·분포는 Python이 계산합니다.
개인 결과지의 설명 문장은 같은 문장별 인원수로 묶어 AI에 전달합니다.
일반 색상 설명만으로 쓰지 않도록 개인별 설명과 강점 원문을 함께 준비합니다.

prompt_text에는 명부의 이름·사번·이메일, PDF 경로를 넣지 않습니다.
자유문장에 이런 값이 섞여 있으면 추가로 가립니다.
다만 작은 조직의 집계는 신원이 추정될 수 있으므로 완전한 익명자료를 뜻하지는 않습니다.
AI 모델 연결은 회사 Dataiku에서 승인되어 제공되는 연결을 사용합니다.

AI 입력 전체 데이터셋에는 조직 식별용 칼럼이 있습니다.
후속 AI 레시피에는 prompt_text 칼럼만 전달하면 됩니다.

shared/leader는 문장 생성 목적을 구분하는 값이며 웹페이지 접근 권한이 아닙니다.
이름이 있는 구성원표와 리더용 집계는 관리자 데이터로 유지하고,
04 Dash 서버에서 로그인 권한에 맞게 조회/표시합니다.
현재 소규모 조직을 자동 숨기는 인원 기준은 두지 않았으며 구성원은 집계만 봅니다.

[birkman_team_cache — 실행 완료 기록]
  latest_attempt.json  가장 최근 실행 상태
  latest_success.json  가장 최근 성공한 실행의 ID와 출력 행 수
원본 PDF를 보관하는 폴더가 아닙니다. AI 호출 결과도 아직 저장하지 않습니다.

3. 이번에 확정한 조직/인원 처리
=============================

그룹 직속 파트:
  팀명이 비어 있어도 파트명이 있으면 part 조직으로 집계합니다.
  direct_part=true, parent_team_key는 빈값입니다.

여러 사업장/근무지:
  사업장과 실근무지를 조직 키에 넣지 않습니다.
  같은 조직 경로의 팀은 근무지가 달라도 한 팀입니다.
  그룹총괄/공장은 기존 합의대로 조직 구분 키에 남기고 표시 경로에서는 생략합니다.
  따라서 공장 칼럼 자체가 다르면 다른 조직 키가 될 수 있습니다.

휴직/출향:
  명부에 남기고, 정상 진단이 있으면 집계에도 포함합니다.

T/A:
  명부에는 포함하고 진단 지표 분모에서는 제외합니다.

PDF 없음 / 추출 실패 / 이름 연결 보류:
  명부에는 포함하고 진단 지표에는 없는 값을 넣지 않습니다.
  기존 1단계의 연결 결과를 사용합니다. 2단계에서 PDF를 다시 찾지 않습니다.

분모:
  맵은 해당 맵의 유효 좌표가 있는 사람 수,
  흥미는 해당 흥미 점수가 있는 사람 수로 각각 계산합니다.
  원본의 실제 0점은 유효한 점수이며, 없는 값과 구분합니다.
  이메일 형식이나 org_status 안내는 진단 수치 집계의 제외 조건이 아닙니다.

4. 실행 후 확인
==============

로그 끝에 '팀·파트·그룹 집계 완료'와 다음 숫자가 나옵니다.
  팀수 / 파트수 / 팀없는직속파트수
  대상직종인원 / 분석가능인원_사번중복없이
  AI입력행수 / AI생성대상행수

birkman_org_summary에서 익숙한 팀 하나와 팀 없는 파트 하나를 확인하면 됩니다.
org_name, member_count, analysis_count, usual_valid_count 정도만 먼저 봅니다.
팀원의 진단이 없는 경우 member_count보다 analysis_count가 작은 것은 정상입니다.
구성원표의 전체 행 수가 명부보다 많은 것도 팀/파트 중복 포함 때문에 정상입니다.

이 단계에서는 오류 목록을 모두 해결하거나 회사 자료를 외부로 보낼 필요가 없습니다.

5. 다음 단계 — AI 설명 생성과 Dash
================================

이번 레시피 실행으로 AI 입력자료와 대상별 프롬프트까지 준비됩니다.
AI 모델 호출, 리포트 문장 생성, Dash 화면, 로그인은 이번 코드에 포함하지 않습니다.

후속 구성:
  1) birkman_ai_inputs를 바로 Prompt Recipe에 연결
  2) 회사 Dataiku의 사용 가능한 LLM 연결에서 prompt_text 사용
  3) 결과를 birkman_ai_reports_raw 데이터셋에 저장
  4) 기본 JSON 형식은 Prompt Recipe에서 확인
  5) Dash에서 응답 항목·근거 ID·대상 구분을 읽고 수치/맵과 함께 표시

자세한 Prompt 설정은 03_Dataiku_프롬프트_설정안내.txt를 참고합니다.
별도 AI 답변 정리용 Python 레시피나 보고서 데이터셋은 추가하지 않습니다.
Dash의 응답 확인·표시 코드는 04_birkman_dash_webapp에 구현했습니다.

AI 출력은 headline, overview, work_patterns, collaboration, leader_actions,
discussion_questions, coverage_note 구조로 요청하도록 프롬프트에 반영했습니다.
소속 구성원용 출력은 leader_actions가 빈 배열이고 리더 비교를 하지 않습니다.
리더용 입력에는 리더와 다른 구성원의 별도 집계가 포함됩니다.
리더의 진단이 없으면 해당 사람의 성향을 추정하지 않도록 되어 있습니다.

AI가 적어주는 각 설명에는 사용한 evidence_id를 함께 남기도록 했습니다.
화면의 작성 근거를 열면 근거 문장/인원 분포를 확인할 수 있습니다.

현재 input_hash는 재생성 대상을 구분할 수 있도록 준비한 값입니다.
변경된 조직만 AI를 다시 호출하는 증분 생성 기능은 현재 구현 범위에 없습니다.
완성 프롬프트가 달라지면 해시도 달라지지만, 재실행 시각만 달라져서는 달라지지 않습니다.

6. 실행이 멈추는 경우
====================

folder not found / dataset not found:
  Inputs/Outputs에 위의 2개 입력과 4개 출력이 실제 연결됐는지 확인합니다.
  이름으로 폴더를 찾지 못하면 코드 상단 설정을 폴더 ID로 바꿉니다.

latest_success.json을 읽지 못함:
  기존 birkman_cache가 입력에 연결됐는지 확인합니다.
  1단계 PDF 추출 레시피가 끝까지 성공했을 때 이 기록이 생성됩니다.

개인 결과표와 추출 완료 기록이 다름:
  1단계와 2단계를 동시에 실행하지 말고 1단계 완료 후 실행합니다.
  앞 단계가 갱신 중일 때 중간 상태를 집계하지 않기 위한 확인입니다.

사번 중복 또는 비어 있음:
  현재 사용자가 사번 중복은 없다고 확인한 상태입니다.
  실제로 이 메시지가 나오면 명부 중복으로 인원수가 늘어난 경우이므로 확인합니다.

실행 중 출력 실패:
  일부 출력만 갱신될 수 있습니다. 원인 해결 후 같은 레시피를 다시 실행합니다.
  04 웹앱은 세 데이터셋의 aggregation_run_id/source_run_id 및 완료 기록을
  모두 대조한 뒤 동일 실행 결과만 사용합니다.

7. 확인한 범위
==============

코드는 Dataiku에서 직접 사용할 본 레시피입니다. 별도 데모 화면이나 가짜
진단 결과를 배포하지 않습니다. 내부 점검용 데이터는 전달 ZIP에 포함하지 않습니다.

사내 서버에 직접 접속해 실행한 것은 아니므로 실제 실행은 사용자 Dataiku에서 합니다.
기존에 실행 성공한 read_schema/iter_rows/write_schema/get_writer 방식을 사용했습니다.

확인 완료:
  팀 없이 그룹 아래에 있는 파트와 여러 근무지의 같은 팀 집계
  진단 없는 직원/T/A/휴직/출향자의 명부·분모 처리
  팀과 파트에 중복 소속된 직원의 전체 인원 중복 방지
  실제 제공된 시그니처 PDF에서 추출한 점수·좌표·조직 키의 연계
  구성원용/리더용 AI 입력 분리와 직접 식별자 제외
  긴 프롬프트의 길이 제한 및 생략 근거 표시
  Dataiku API 대체 환경에서 전체 출력과 중간 실패 완료표시 처리
