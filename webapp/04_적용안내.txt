[수정한 보고서 동작]
1. 맵
- 빨강 왼쪽 위 / 초록 오른쪽 위 / 노랑 왼쪽 아래 / 파랑 오른쪽 아래를 유지합니다.
- 흥미 별, 평소행동 다이아몬드, 욕구 원, 스트레스행동 네모를 구분합니다.
- 욕구와 스트레스는 한 맵에 표시하지만 좌표를 합치거나 옮기지 않습니다.
- 두 좌표가 정확히 같으면 원과 네모가 겹칩니다. 서로 다르면 각각 원래 위치에 표시합니다.
- 확인되지 않은 항목은 그대로 미확인 처리합니다. MAP_COLOR_CONFLICT를 임의로 정상 판정하지 않습니다.
- 현재 스트레스 정도를 측정한 값으로 읽지 않도록 설명을 추가했습니다.
- 개인 카드는 그 구성원 한 사람의 네 기호를 표시합니다.

2. 조직지향점
- 개인 결과의 네 막대와 팀 인원 분포를 가운데 정렬합니다.
- 가운데 정렬은 표시 방식입니다. 중심선의 좌우가 서로 반대되는 성향은 아닙니다.
- 개인 막대는 그 사람의 가장 긴 막대를 기준으로 재현한 상대 길이입니다. 공식 점수나 직원 간 절대 비교값이 아닙니다.
- 팀 막대는 개인별 최상위 분야 인원을 이 항목 반영 인원으로 나눈 분포입니다. PDF 길이를 직원끼리 평균내지 않습니다.
- 동률은 해당 분야 모두에 포함하므로 네 분야의 합계가 반영 인원을 넘을 수 있습니다.
- 기획/전략, 영업/마케팅, 운영/기술, 관리/회계의 근무환경 설명과 미확인 인원을 표시합니다.
- 같은 색이어도 맵과 조직지향점은 다른 항목임을 설명합니다.

3. 읽는 흐름
핵심 요약 → 읽는 법 → 흥미 → 평소행동 → 욕구·스트레스 → 팀 운영에 적용하기.
뒤쪽 참고자료: 구성 비교·조직지향점, 흥미 점수표, 평소행동-욕구 비교, 리더 비교, 구성원 카드.
AI 해설은 팀 운영 부분에 모았습니다. 욕구를 근거로 작성한 문장을 평소행동의 설명처럼 배치하지 않습니다.
본문에서 발췌한 AI 해설의 전문은 필요한 경우 뒤쪽 해설 전문 페이지에 이어집니다.
화면 위의 ‘설명 전문 · 작성 근거’는 접어서/펼쳐서 확인할 수 있습니다. 이 패널은 A4 밖에 두어 펼쳐도 종이 배치가 밀리지 않습니다.
해당 패널 자체는 인쇄되지 않습니다. 개인 설명 전문은 구성원 상세에서 확인합니다.

4. A4와 인원 증가
모든 쪽은 A4 세로 210mm × 297mm입니다. 화면에서는 종이 전체를 화면 폭에 맞춰 축소합니다.
글꼴과 이미지가 준비된 뒤 브라우저가 실제 높이를 측정해 다음 장으로 이어갑니다.
표는 머리글·열·테두리를 유지하고, 아주 긴 셀도 표 안에서 다음 페이지로 이어집니다.
목록의 글머리표와 번호를 유지합니다. 구성원 카드는 두 열로 배치하며, 원문 발췌 길이를 제한해 카드 한 개가 한 장보다 커지지 않도록 했습니다.
이름·문장은 셀 안에서 줄바꿈합니다. 좌표나 글자를 임의로 축소하거나 잘라서 한 장에 끼워 넣지 않습니다.
페이지 수는 인원수와 원문 길이에 따라 늘어나며 목차·쪽 번호도 다시 계산됩니다.

AUTH_MODE = "preview"

앱의 이메일별 권한은 인증 운영 모드로 전환한 뒤 접속자별로 적용됩니다.

나중에 위 한 줄을 지우거나 #으로 주석 처리하고, 아래 둘 중 하나만 주석 해제합니다.
# AUTH_MODE = "email_otp"
# AUTH_MODE = "password"
세 설정 중 활성화된 한 줄만 남기면 됩니다. 인증 기능 전체를 다시 붙여 넣거나 별도 코드를 합칠 필요가 없습니다.
운영 모드는 HTTPS 주소가 필요합니다. DSS 계정 없이 웹앱 주소에 들어갈 수 있도록 하는 설정은 DSS 관리자에게 별도로 요청해야 합니다.
웹앱 접근 설정과 앱 안의 본인 인증·권한은 별개입니다.

[메일 없이 운영하는 방법: password]
메일 발송이나 Dataiku 사용자 계정 없이 쓸 수 있는 방식입니다.
‘담당자가 최초 본인 확인 → 일회용 등록코드 전달 → 직원이 비밀번호 설정 → 이후 이메일+비밀번호 로그인’입니다.
관리자가 직원마다 비밀번호를 정하거나 보관할 필요는 없습니다.
이메일은 로그인 ID로 사용하며, 입력만으로 이메일 소유권을 인증하는 기능은 아닙니다.
본인 확인은 등록코드를 전달할 때 담당자가 대면 또는 이미 신원이 확인된 사내 연락수단으로 수행합니다.

첫 관리자 전환 순서:
1. 아직 preview 모드인 상태에서 관리자 메뉴를 엽니다.
2. 대상 직원을 최초 관리자 본인으로 선택합니다.
3. 본인 확인 체크 후 ‘일회용 등록코드 발급’을 누릅니다.
4. 화면에 나온 코드를 따로 보관합니다. 30분 유효합니다.
5. 코드 맨 위의 preview 줄을 주석 처리하고 password 줄을 주석 해제합니다.
6. 저장·백엔드 재시작 후 HTTPS 주소로 접속합니다.
7. 로그인 화면에서 본인 회사 이메일, 등록코드, 새 비밀번호를 입력하고 ‘비밀번호 설정’을 누릅니다.
8. 위쪽 로그인 칸에 본인이 설정한 비밀번호를 입력해 로그인합니다.

다른 직원 추가:
1. 관리자 메뉴에서 대상자를 고릅니다.
2. 조회 역할(hr / team_leader / part_leader / member), 조회 조직, 로그인 허용을 지정하고 먼저 저장합니다.
3. 본인 확인을 마친 뒤 확인 체크를 하고 등록코드를 발급합니다.
4. 코드를 해당 직원에게 직접 전달합니다. 앱에서 메일을 자동 발송하지 않습니다.
5. 직원은 로그인 화면에서 자신의 비밀번호를 설정합니다.
권한 저장은 발급된 등록코드를 폐기하므로, 권한 저장 후 등록코드를 발급하는 순서를 지킵니다.

등록코드/비밀번호 동작:
- 등록코드는 30분·1회 유효합니다. 재발급하면 이전 코드는 무효입니다.
- 직원은 15~128자의 비밀번호를 직접 정합니다. 기존 회사 계정과 다른 비밀번호를 사용합니다.
- DB에는 개인별 salt가 포함된 PBKDF2-SHA256 해시만 보관합니다. 관리자도 비밀번호를 볼 수 없습니다.
- 로그인 및 등록 실패 횟수를 제한합니다.
- 비밀번호 재설정은 담당자의 재확인과 등록코드 재발급으로 진행합니다.
- 새 비밀번호 설정이 완료되면 기존 로그인 세션은 모두 종료됩니다.
- 등록코드 발급만으로 기존 비밀번호가 즉시 바뀌지는 않습니다.
- 이메일+사번을 직접 입력하는 방식, 공용 비밀번호, 사내 IP만으로 개인을 구분하는 방식은 사용하지 않습니다.

다른 대안:
- 인증 앱 TOTP: 메일 없이 인증번호를 만들 수 있지만 최초 등록에서 본인 확인과 휴대폰 변경 대응이 필요합니다. 이번 코드에는 구현하지 않았습니다.
- 패스키: 등록 이후 지문/기기 잠금으로 로그인할 수 있으나 HTTPS 도메인, 등록·복구 절차와 추가 구현이 필요합니다. 이번 코드에는 구현하지 않았습니다.
- 회사 기존 로그인 연동은 현재 불가하다는 조건을 유지했습니다.
