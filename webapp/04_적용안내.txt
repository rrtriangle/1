04 Dash 웹앱 코드만 교체합니다. 01 PDF 추출, 02 조직 집계, 03 프롬프트 레시피와 데이터셋 구조는 그대로입니다.
레시피를 다시 돌리거나 새 데이터셋·패키지를 만들 필요가 없습니다.

[적용 순서]
1. 기존 웹앱 Python 코드를 따로 보관합니다.
2. 04_birkman_dash_webapp.py 전체를 복사해 Dataiku Dash 웹앱 Python 편집기 전체를 교체합니다.
3. 맨 위 설정을 기존에 쓰던 값으로 옮깁니다.
   AUTH_MODE, MAIL_CHANNEL_ID, FIRST_ADMIN_EMAIL, AUTH_FOLDER_ID, TEAM_CACHE_FOLDER, EXTRACT_CACHE_FOLDER, 데이터셋 이름
4. 저장하고 웹앱 백엔드를 재시작한 뒤 브라우저를 새로 엽니다(Ctrl+F5).

[보는 사람 — 이번에 바뀐 점]
- 팀 보고서는 조직장과 인사(hr) 권한만 봅니다. 팀원에게는 팀 보고서를 공개하지 않고 '내 결과'만 보여줍니다.
- 조직장은 명부의 직책명으로 자동 지정됩니다. 관리자 화면에서 한 명씩 등록하지 않아도 됩니다.
    팀장 → 그 팀 + 하위 파트 / 파트장 → 그 파트 / 그룹장·실장 등 → 그룹 직속 같은 그 밖의 조직
- 직책명 목록은 맨 위 TEAM_HEAD_TITLES, PART_HEAD_TITLES, OTHER_HEAD_TITLES 에서 바꿉니다.
- 관리자 화면에서 지정한 권한(인사팀, 추가 조직)은 자동 지정과 합쳐 적용됩니다.
- 자동 지정을 끄려면 AUTO_LEADER_SCOPES = False 로 바꿉니다.

[보고서 순서 — 버크만 맵(흥미·평소·욕구)과 조직지향점 중심]
표지 → 01 읽는 법 → 02 팀이 끌리는 활동(맵의 흥미 ✱) → 03 팀이 일하는 방식(평소행동 ◆)
→ 04 팀이 바라는 환경(욕구 ○) → 05 평소행동과 욕구가 다른 구성원 → 06 리더와 구성원
→ 07 편한 근무환경·조직지향점 → 08 팀 운영 가이드 → 09 구성원 한눈에 보기
→ 참고자료(흥미 점수 10개 영역, 전체 진단자 비교, 번호표, 해설 전문)

흥미 구분
- 맵의 흥미(✱): 맵 위 위치로 보는 흥미. 본문 02에서 중심으로 다룹니다.
  흥미와 평소행동의 색이 다른 구성원을 따로 표시합니다.
- 흥미 점수 10개 영역(숫자·관리·과학·문학 등 0~100점): 참고자료로만 제공합니다.

표지
- 왼쪽: '팀 한눈에 · 버크만 맵' 2×2 색 타일(색마다 흥미·평소·욕구 인원)
- 오른쪽: 보고서 차례(쪽번호)
- 아래: '먼저 해볼 일' 3칸 카드, 평가·배치 근거로 쓰지 않는다는 안내
- 숫자 4칸: 흥미 ✱ / 평소행동 ◆ / 욕구 ○ / 조직지향점

새로 추가된 내용
- 04: 평소 보이는 방식(◆)과 바라는 대우(○)의 색이 다른 구성원 표와 조직장이 기억할 점
- 05: 조직장의 평소행동과 구성원별 욕구를 맞댄 표(가까움 / 부분 조정 / 의식적 조정)와 해볼 일
- 06: 분야별(가장 긴 막대) 구성원 명단
- 08: 욕구 색에 따른 회의·피드백·업무 지시·공지 팁. AI 해설이 없어도 표시됩니다.
- 09: 구성원 카드 — 작은 맵, 네 기호의 색(경계면 '파랑(노랑 쪽)'), 결과지 원문(평소·욕구·스트레스),
       다음 1:1 대화 질문, 편한 근무환경
- 표지: '먼저 해볼 일'이 AI 해설이 없을 때도 규칙으로 채워집니다. 평가·배치 근거로 쓰지 않는다는 안내를 넣었습니다.
- 보고서 문구는 팀 보고서는 '팀장', 파트 보고서는 '파트장', 그 밖의 조직은 '조직장'으로 표시합니다.
- 시그니처의 9개 구성요소는 사용하지 않습니다.

해석 기준(맨 위 설정)
- BORDER_BAND = 0.10 : 가운데 선 가까이 있으면 이웃 색을 함께 표시
- NEEDS_GAP = 0.6     : 색이 같아도 두 기호 거리가 이 이상이면 04 표에 포함
- MIN_GROUP_FOR_PATTERN = 5 : 이 인원 이상일 때만 '절반 이상이 같은 색', '팀에 없는 색' 문구 표시

[운영 안정화]
- 화면이 60초마다 다시 그려지지 않습니다. 60초마다 로그인 만료 여부만 확인하고, 만료됐을 때만 로그인 화면으로 바뀝니다.
- 60초마다 데이터셋 전체를 다시 읽지 않습니다. 완료 기록만 확인하고 집계가 바뀌었을 때만 새로 읽습니다.
- 자료 검증에 실패하면 원인(예: '집계 표의 행 수와 완료 기록이 다릅니다: birkman_org_members')이 화면과 웹앱 로그에 표시됩니다.
- 테스트 모드(preview)에서는 최초 관리자 본인의 등록코드만 발급됩니다. 다른 직원 코드는 운영 모드에서 발급합니다.
- 비밀번호 로그인의 '15분 5회' 제한은 실패한 시도만 셉니다.
- 사용하지 않던 코드(숨은 맵 선택, 사용하지 않는 함수·import)를 정리했습니다.

[확인 범위]
사내 Dataiku 서버에서 직접 실행한 것은 아닙니다.
01~03 결과와 같은 구조의 가상 자료(5개 조직, 23명)로 다음을 확인했습니다.
- 팀·파트 보고서 화면과 A4 페이지 배치, 콘솔 오류 없음
- 팀장·파트장·그룹장·팀원·인사 권한 범위, 팀원의 다른 사람 상세 조회 차단
- 비밀번호 로그인, 60초 확인 후 보고서가 다시 그려지지 않음
- 완료 기록이 같을 때 데이터셋을 다시 읽지 않음, 검증 실패 시 원인 문구 표시
실제 회사 데이터의 직책명 표기(예: '팀장' 외 다른 표기)가 다르면 맨 위 직책명 목록에 추가해 주세요.
