# Dataiku DSS 설치 안내

Dataiku DSS 14 기준으로 작성했다. **이 절차는 개발 환경에 Dataiku가 없어 실제 DSS에서 실행해 보지 못했다.**
로컬에서는 같은 코드를 "미리 만들어진 Dash 앱에 붙이는" 방식과 하위 경로에 띄운 상태로 확인했다.
DSS 안에서 오류가 나면 오류 메시지를 그대로 전달해 주면 된다.

## 1. 코드 환경

Python 코드 환경을 만들고(또는 기존 환경에) 다음 패키지를 넣는다. `requirements.txt`와 같다.

```
pandas  numpy  openpyxl  plotly  dash  scikit-learn  networkx
```

- 확인한 버전: Python 3.13, dash 4.5, plotly 7.1, pandas 3.0, scikit-learn 1.9, networkx 3.7.
  더 낮은 버전에서는 실행해 보지 않았다. 최소 Python 3.10, dash 2.17 이상을 권장한다.

## 2. 프로젝트 라이브러리에 코드 올리기

프로젝트 > Libraries 에서 `python/` 아래에 `hrli` 폴더를 통째로 만든다(하위 `web` 폴더 포함).
zip으로 받은 경우 파일 이름 끝의 `.txt`를 지워 `.py`로 되돌린 뒤 올린다.

```
python/
  hrli/
    __init__.py  auth.py  analysis.py  classify.py  config.py  db.py  ingest.py
    metrics.py  sample_data.py  seed.py  summary.py
    web/
      __init__.py  admin.py  app.py  charts.py  common.py  pages.py  person_plan.py  style.py
```

## 3. 관리 폴더 만들기

Flow에서 관리 폴더(Managed folder)를 하나 만든다. 이름 예: `hrli_data`.

- **DSS 서버의 로컬 파일시스템에 있는 폴더여야 한다.** DB 파일(`hrli.sqlite3`)과 업로드 원본(`raw/`)이 여기에 쌓인다.
  S3 같은 원격 저장소 폴더에서는 `get_path()`가 동작하지 않아 쓸 수 없다.
- 이 폴더에는 직원 개인정보가 들어가므로 프로젝트 권한을 교육 담당자 등 필요한 사람으로 제한한다.
- 폴더를 지우면 누적 데이터가 모두 사라진다. DSS 백업 대상에 포함되는지 확인한다.

## 4. 초기 설정(한 번만)

웹앱과 같은 코드 환경으로 Python 노트북을 열고 `dataiku/setup_notebook.py` 내용을 붙여 넣은 뒤,
`admin_email`을 본인 이메일로 바꿔 실행한다. DB가 만들어지고 첫 시스템 관리자가 등록된다.

## 5. 웹앱 만들기

1. 프로젝트 > Webapps > 새 웹앱 > Code webapp > **Dash** 를 고른다.
2. Settings에서 코드 환경을 1번의 환경으로 지정한다.
3. Python 탭의 예시 코드를 모두 지우고 `dataiku/webapp_backend.py` 내용을 붙여 넣는다.
4. 파일 안의 `DATA_FOLDER`, 메일 발송 설정(아래 6번)을 실제 값으로 바꾼다.
5. 저장하고 백엔드를 시작한다.

Dataiku는 웹앱 백엔드를 한 프로세스로 띄운다. 이 앱은 SQLite 파일 하나를 쓰므로 그 구성이 맞다.

## 6. 인증 메일 발송

로그인은 "등록된 이메일 입력 → 메일로 받은 6자리 코드 입력" 방식이다. 메일을 보낼 방법이 하나 필요하다.

| 방법 | 설정 | 확인할 것 |
|---|---|---|
| Dataiku 메일 채널 | `auth.dataiku_mailer(channel_id=..., project_key=...)` | DSS 관리자가 메일 채널을 만들어 두었는지, 웹앱 실행 계정이 그 채널을 쓸 권한이 있는지 |
| 사내 SMTP 서버 | `auth.smtp_mailer(host=..., sender=..., port=...)` | DSS 서버에서 SMTP 서버로 접속이 되는지, 발신 주소가 허용되는지 |

- SMTP 비밀번호가 필요하면 코드에 직접 적지 않는다.
- 메일 설정이 없거나 발송에 실패하면 로그인 화면에 "인증 코드를 보내지 못했습니다"가 나오고, 사유는
  데이터 관리 > 업로드·수정 이력 > 접근 이력에 남는다.
- 코드는 10분 뒤 만료되고, 5번 틀리면 폐기되며, 60초 안에는 다시 보낼 수 없다(`hrli/config.py`에서 조정).

## 7. Dataiku 계정이 없는 사람에게 열기

기본 상태의 웹앱은 Dataiku에 로그인한 사람만 열 수 있다. 계정이 없는 사람도 쓰게 하려면
**DSS 관리자가 이 웹앱을 공개 웹앱으로 등록**해야 한다(Administration > Settings > Login & Security 의
인증 예외 목록에 `프로젝트키.웹앱ID` 추가 후 웹앱 백엔드 재시작). 정확한 메뉴 이름은 DSS 버전에 따라 다를 수 있다.

공개 웹앱으로 등록하면 Dataiku는 접속자를 확인하지 않는다. 그 뒤로는 **이 앱의 이메일 인증이 유일한 관문**이다.
따라서 다음을 지킨다.

- DSS가 HTTPS로 서비스되는지 확인하고 `attach(..., https=True)`로 둔다.
- 사내망에서만 접속되는 주소인지 확인한다. 인터넷에 노출된 DSS라면 공개 웹앱으로 열지 않는다.
- 사용자 등록은 최소한으로 하고, 퇴직·이동자는 데이터 관리 > 사용자에서 바로 "중지"한다.
- 공개 등록 전에 보안 담당 부서의 승인을 받는다. 인사 데이터가 들어 있기 때문이다.

공개 등록이 허용되지 않으면, 사용자를 Dataiku 계정이 있는 사람으로 한정하고 그대로 쓰면 된다.
이 경우에도 앱 안의 이메일 인증과 역할 구분은 그대로 동작한다.

## 8. 데이터 넣기

데이터 관리 > 업로드·검토·승인 화면에서 두 가지 방법을 쓸 수 있다.

- **파일 업로드**: Excel/CSV 파일을 직접 올린다.
- **Dataiku 데이터셋에서 불러오기**: 프로젝트에 올려 둔 데이터셋 이름을 입력한다. 내용이 파일 업로드와
  똑같은 검토 절차(비교 → 검토 → 승인)로 들어간다.

어느 쪽이든 승인하기 전에는 통계에 반영되지 않는다. 처음에는 직원 명부를 기준월 순서대로 먼저 올리고,
그다음 교육 이력을 올린다. 원본 컬럼명이 기본값(사번, 성명, 교육명, 시작일 등)과 다르면 `column_mapping`
테이블에 별칭을 추가해야 한다(README의 "실제 데이터 연동 전에 정해야 할 것" 참고).

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 백엔드가 시작되지 않고 `No module named hrli` | 2번의 폴더 위치(`python/hrli/`)와 파일 확장자(.py) |
| `No module named dash` 등 | 웹앱 Settings의 코드 환경 지정 |
| `get_path` 관련 오류 | 관리 폴더가 서버 로컬 파일시스템인지(3번) |
| 로그인 화면은 뜨는데 코드가 안 옴 | 6번의 메일 설정, 접근 이력의 "인증 코드 발송 실패" 사유 |
| 로그인 직후 다시 로그인 화면으로 돌아감 | HTTP로 접속 중인데 `https=True`로 둔 경우. 접속 주소와 설정을 맞춘다 |
| 계정 없는 사람이 접속하면 Dataiku 로그인 화면이 뜸 | 7번의 공개 웹앱 등록과 백엔드 재시작 |
